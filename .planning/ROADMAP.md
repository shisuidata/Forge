# Roadmap: Forge

## Overview

This roadmap contains only the currently authorized S0 Design Partner / Problem Baseline. It converts the accepted short-term reset in `REQ-2026-08-25-023` into one coherent evidence gate: identify one eligible small data team and make the partner, domain, datasource, semantic authority, real questions, privacy/authorization boundary, and manual-process baseline explicit and reviewable. No runtime or product-surface implementation phase follows automatically; any later phase requires new evidence and explicit user approval.

## Phase Details

### Phase 1: S0 Design Partner / Problem Baseline
**Goal**: The product owner has a complete, reviewable problem baseline for one eligible small data team, sufficient to judge whether a future trusted-answer slice is grounded in a real problem and legally testable boundary.
**Depends on**: Nothing (first phase)
**Requirements**: S0-01, S0-02, S0-03, S0-04, S0-05, S0-06, S0-07
**Success Criteria** (what must be TRUE):
  1. The product owner can identify one qualifying small data-team design partner and show that it already has a queryable database or warehouse, recurring ad hoc questions, and incomplete semantic governance.
  2. The partner baseline names exactly one bounded business domain, one existing queryable datasource, and one semantic owner or steward authorized to confirm definitions.
  3. A reviewable corpus contains real historical questions and a defined intake for ongoing questions from actual work; the corpus is not reverse-designed for a Forge demonstration.
  4. The partner and product owner can review one explicit privacy and authorization boundary covering data locality/private deployment, least privilege, permitted evidence, Secret/PII exclusions, retention, exit, and deletion.
  5. The product owner can compare future behavior against a documented current manual process covering intake, SQL authorship, clarification count, review, delivery, and known silent-error discovery.
