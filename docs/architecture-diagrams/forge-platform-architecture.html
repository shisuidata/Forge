04 · 端到端任务流程

从用户问题到证据化报告

每个高风险步骤都有持久化状态、人工审批和可恢复边界。

TASKRUN · QUERYRUN · ARTIFACT
A. 输入与澄清
01

渠道接收消息

验证服务密钥，按事件 ID 去重，映射可信用户身份。

02

创建 TaskRun

Pi 创建唯一任务，记录渠道、会话、组织、团队和用户。

03

需求与指标澄清

纯问候或信息不足时进入 needs_input，不生成 SQL。

04

结构化 Artifact

Skill 只能通过受控工具提交经过 Schema 校验的产物。

B. 查询准备、审核与可信执行
05

Forge 查询规划

Registry 注入 → 模型生成 Forge JSON → Schema 和 Lint 校验。

06

确定性编译

Compiler 生成方言 SQL，并保存 SQL 摘要与 Registry 版本。

07

人工审核 SQL

用户审核固定 SQL；审批绑定 QueryRun ID 与 SQL hash。

08

只读执行

Forge 复核身份、过期、结构漂移和权限后执行。

C. 证据分析、补查与交付
09

查询结果 Artifact

保存列、行、截断状态、执行耗时和证据引用。

10

证据化分析

Finding 只能引用真实 qr_*#row:N；假设不能冒充结论。

11

一次性补查

只允许从模型建议中选择一次；子任务仍需独立 SQL 审批。

12

确定性报告

报告不得扩大分析结论；Markdown 由服务端渲染。

全流程可靠性与安全门禁每个阶段都可以解释、恢复和审计

StageAttempt

模型和 Forge 调用都绑定尝试次数、租约、超时与幂等键。

重启恢复

启动只回收过期租约并恢复可重试状态，不自动重放模型或 SQL。

Forge 独立否决

SQL hash 不匹配、身份不符、审批过期、Registry 漂移或非只读账户均拒绝执行。

渠道幂等

重复消息不创建第二个 TaskRun；重复按钮不执行第二次 SQL。

模型版本固定

新任务读取当前激活模型；在途任务和重试固定原模型版本。

证据边界

报告只能复用 AnalysisArtifact 中已验证的 finding 和 evidence。

关键状态

created已创建
needs_input等待补充
waiting_approval等待 SQL 审批
querying只读执行中
ready_analysis待分析
incomplete证据不足
ready_report待报告
completed已完成
高风险动作必须人工确认；查询完成不等于业务分析任务完成。
05 · 关键闭环

系统不是单向流水线，而是受控循环

每个循环都有终止条件、人工确认和持久化状态，禁止模型无限自主重试。

BOUNDED LOOPS · HUMAN IN THE LOOP

闭环 A：需求澄清与 SQL 审核

用户信息不足或拒绝 SQL 时，回到需求而不是直接修改并执行 SQL。

用户问题自然语言需求
需求澄清needs_input
准备 SQLForge JSON → SQL
审核批准 / 拒绝

闭环 B：证据不足时的一次性补查

分析只能补查一次，且只能选择 AnalysisArtifact 给出的建议查询。

父查询结果QueryResultArtifact
分析不完整incomplete + 建议
子 QueryRun独立 SQL 审批执行
合并证据

闭环 C：模型配置验证与切换

配置失败不能替换当前可用模型；修正后重新验证，无需重启服务。

编辑模型配置Provider / 协议 / 模型
真实验证连接、工具调用、结构化输出
生成版本不可变 revision
激活CAS

闭环 D：Registry 同步与结构变更审核

数据库结构变化先形成差异草案；危险变更必须审核后才发布新 Registry 版本。

数据库内省只读读取 Schema
结构差异草案新增、删除、类型和约束
人工审核危险变化明确确认
发布Revision
所有循环都是有界循环：澄清等待用户、SQL 等待审批、补查最多一次、模型和 Registry 切换必须人工激活。

07 · 控制面与下一阶段

模型控制面与 Registry Studio

配置可以方便切换，但必须保留版本、验证、审计和回滚，不能依赖进程重启。

PHASE 4.4 / 4.5

阶段 4.4 · 模型配置控制面用户切换模型无需重启服务

1. 模型配置

Provider、协议、Base URL、模型、能力和密钥引用。

2. 配置验证

真实检查连接、Tool Calling 和结构化输出。

3. 不可变版本

验证成功生成 ModelProfile Revision。

4. 原子激活

按组织、团队和 Stage 更新 ActiveBinding。

失败关闭

未配置 LLM：不调用模型、不生成 SQL，明确返回“尚未配置 LLM”。配置错误：保留旧的激活版本，并返回有界的“LLM 配置错误”；原始 Key 和服务端响应不进入用户消息。

Forge 查询规划模型

作用域：forge.query_planning。QueryRun 保存 model revision。

Pi Skill 模型

澄清、指标、分析、报告可统一默认或按 Stage 覆盖。

切换语义

新任务读取新版本；在途任务和 retry 固定旧版本；失败不影响当前版本；支持一键回滚和切换审计。

阶段 4.5 · Registry Studio结构层多视图与安全编辑

表格视图

浏览和维护表、字段、类型、约束与注释。

DDL 视图

按方言确定性渲染；编辑只形成草案。

ER 图

显示真实外键；推断关系必须人工确认。

JSON 视图

高级用户查看统一结构模型原文。

唯一真相源：Canonical Schema

数据源、catalog/schema、表、字段、类型、nullable、default、主键、外键、唯一约束、索引、注释、标签和版本元数据。

安全编辑流程

数据库内省 / DDL 导入 / 表格编辑 / ER 编辑 → RegistryDraft → Schema 校验 → 确定性差异 → 人工审核 → RegistryRevision。

不直接执行数据库 DDL

结构层编辑不等于 ALTER TABLE。数据库 Migration 是未来独立的高风险能力。

漂移与并发

删除字段、类型收窄、nullable 收紧、PK/FK 变化必须审核；发布使用 revision CAS，保留完整 diff 和回滚点。

共同设计原则

一个真相源视图和进程不能各自保存互相漂移的状态。
先验证再激活配置保存不代表配置可用；验证失败不影响当前版本。
在途任务固定模型和 Registry revision 在任务开始时快照固定。
全程可审计谁在何时修改、验证、激活和回滚都必须可追踪。
阶段 4.4 优先于阶段 4.5：先解决模型切换与配置失败关闭，再建设结构层工作台。
