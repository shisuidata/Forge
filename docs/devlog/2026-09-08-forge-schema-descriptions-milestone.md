# Forge 的一次局部突破：把接口讲清楚，而不是继续堆提示词

> 未发布文案。事实来源为 REQ-065；本次只归档并提交 GitHub，不发布软件版本或分发内容。完整数据与优化动作见[技术简报](../archive/benchmarks/benchmark-luna-schema-descriptions-2026-09-08.md)。

## 主文案

今天，Forge 有一个值得记下来的局部突破。

在这一轮固定的 8 道开发题、两次重复测试中，增强后的 Forge EX 得分是 **12/16，75%**；同期 Direct SQL 是 **10/16，62.5%**。两个重复分别都是 **6/8 对 5/8**。

只谈这轮数据，可以明确说：**Forge 得分超过了 Direct SQL，高 12.5 个百分点。**

这次没有换更大的模型，没有追加重试，也没有让编译器猜着补列。我们做的事情更小：把工具接口的语义讲清楚。

此前审计发现，模型使用的 strict Schema 保留了结构约束，却去掉了原 Schema 的说明。模型知道 JSON 可以有哪些字段，但“声明一个 CTE”“把它放进 FROM”“把结果导出给下一层”，不是同一件事。

于是，我们只给五个关键接口补上经过审核的说明：

- `scan`：先绑定数据来源；声明 CTE 不等于引用了它。
- `cte`：下一层能用哪些列，由这一层的 `select` 决定。
- `agg`：定义聚合不等于把聚合结果输出。
- `window`：同层过滤与跨层导出有不同边界。
- `select`：中间层导出必要字段，最终层只返回问题要求的答案。

模型、Prompt、上下文、字段顺序、Compiler 和评分都保持不变。围绕这个单一变量，我们按 ABBA 顺序完成 64 次真实请求，保留所有原响应，再重放检查 SQL、执行状态和评分；没有补跑追分。

这轮结果的意义，不是证明“JSON 天然优于 SQL”，而是留下一个值得继续研究的观察：**把 DSL 的接口含义表达清楚，这个窄改动在本轮伴随了更高的最终答案得分。** 五条说明各自贡献多少、能否推广到更多题，还没有得到证明。

好消息也不能把坏消息挤掉。虽然两个重复的总分都领先，但改善的题并不相同；第二个重复还有一道原本正确的控制题答错。我们事先约定的稳定改善、零回退和控制全对门槛，没有全部通过。

所以，**里程碑记下，候选暂不启用。**

16 是作答次数，不是 16 道独立题；这也不是新的全量基准或统计显著性结论。我们保留这次得分领先，同时保留回退、成本和原始证据。工程上的进展，不必靠省略限制才能成立。

## 短文案

Forge 在一轮固定小样本实验中取得了局部突破：8 道开发题各跑两次，增强后的 Forge EX/Contract 均为 **12/16（75%）**，同期 Direct SQL 为 **10/16（62.5%）**，两个重复均为 **6/8 vs 5/8**。

本轮只为 `scan/cte/agg/window/select` 补充模型可见的工具 Schema 语义说明，没有换模型、改评分或追加重试。64 次真实请求与原响应重放证据完整保留。

这不是总体优势结论：目标题改善尚未稳定复现，且有控制题回退。我们记录这次领先，但保持候选默认关闭，暂不发布版本。

## 使用口径

- 标题及节选必须保留“本轮”或“限定样本”，不能只摘“Forge 准确率 75%”。
- 领先幅度是 **12.5 个百分点**，不是“提升 12.5%”；不把 16 次重复作答改写成 16 道独立题。
- 不称“历史首次”“全面超过”“统计显著”或“已经上线”。历史上已有其他定向样本局部领先。
- 成本如需引用：本轮共 222,015 tokens；处理组相对对照组的双臂总 tokens +3.39%，Forge 每正确答案 tokens −11.73%。不是比 Direct 更省，也不是人民币结算价；不承诺订阅免费。
- 技术数据以[实跑 JSON](../archive/benchmarks/benchmark-luna-schema-descriptions-2026-09-08.json)为源，回退与未通过门槛不能从对外版本中删除。
